## Implementation

- New dashboard Blade supplies URLs through Grocy U, localized copy, scoped purchase flow DOM and only dashboard/CSS assets.
- Dashboard script strictly validates private DTO version, exact keys, session states/IDs/counts/dates and cursors; dynamic content uses text nodes. Separate active/completed GET paging deduplicates sessions. Statistics are independent of page size.
- One explicit New session POST with `{}` disables during requests, validates open trip ID before navigating, and locks after ambiguous responses. Refresh/review guidance recovers empty sessions without automatic POST retry.
- Open sessions offer Resume/Review, reviewing sessions Review, completed sessions Review. Reviewing Resume is deliberately omitted because existing capture rejects all non-open resume payloads and existing review only allows Continue scanning while open; changing that lifecycle was outside the approved task.
- Printed receipt totals use Grocy currency and price display precision, with no invented amount for null totals and explicit missing receipt/printed-total notices. Completed cards distinguish Created and Completed dates.
- Review discard confirmation covers all trip-scoped research/receipt drafts; pending direct/research/receipt mutations and commit block leaving. Capture pending/ambiguous camera saves block leaving and unsaved input requires confirmation. Completed summary's old Start new trip link is now labeled Back to dashboard and uses the guarded action.
- Existing camera ordering, receipt/research/queue/controller ordering, approval and Commit safeguards are preserved. Scanner-only fixture behavior remains intact; production bare capture renders the dashboard. Fixture server aliases model actual capture/review URLs without bypassing dashboard zero-write checks.
- Assets/fixtures synchronize at `2.6.22`, customization marker `ATECHPCS-grocy_AI-45`, portable module unchanged. README/CUSTOMIZATIONS and verification document describe behavior and remaining phone acceptance.

## Review fix round 1

Settled upload jobs retained `status: uploaded`/`file: null` metadata and were incorrectly counted as dirty solely because the upload array was nonempty.

- Added per-trip cancellation pending counts before POST and released them in `finally`, including HTTP failure, invalid result and trip switches. Back remains blocked across all pending trip cancellation scopes. Current-trip Delete and Commit stay disabled; duplicate cancellation is rejected and cancellation cannot start during a pending stock commit.
- Cancellation success/failure UI ownership now checks both current and requested trip IDs. A stale success cannot erase a still-loading different trip, and a stale failure cannot put its deletion error on another trip.
- Only unfinished upload jobs count toward the Back discard warning. Actual successful upload can leave without a false prompt; failed and queued jobs still warn. Pending upload continues to block Back before any discard prompt.
- Added nine browser regressions covering delayed cancellation success/HTTP/invalid payload, selected/reading trip ownership, and actual successful/failed/queued upload flows. The pending-delete tests also pin disabled current-trip Commit and Delete.

## Final whole-branch fix wave

Confirmed `committed` results (including normalized `already_committed`) remain authoritative and may leave even if their follow-up GET failed.
