The prior full release result belongs to the initial Task 3 commit; targeted review fixes reran affected browser and complete PHP/node gates.

Summary entry/back performs zero writes and retains the mounted receipt/research editors. Same-trip reload retains summary state and unsaved drafts. Quantities come from active included item allocations, displayed separately with each reviewed price. Scan rows retain leading-zero UPCs and neutral purchased quantities with unverified effective-unit labels; differing barcodes may carry different stock multipliers and are never summed as catalog units. Receipt-only rows use catalog purchase units when available. Paired scans do not duplicate allocation quantities. Receipt-only items are included; ignored amounts, tax/savings adjustments, accepted differences and full receipt audit totals are distinct from purchases. Missing product/unit metadata is explicitly unavailable.

The server readiness and checksum remain authoritative. Commit uses the existing confirmed-checksum request and confirmation, with a separate in-flight guard. Errors and ambiguous results require reload/recheck before another attempt; success cannot recommit. Direct trip/scan edits remain guarded through settlement and a subsequent authoritative readiness read, with owner state retained across reloads and trip changes. All outcomes and errors return to the original trip summary when still selected; failed reads preserve known partial progress. Already-committed responses are treated as confirmed success. Late responses remain owned by the original trip. Product creation means catalog creation; stock changes happen only through Commit purchase.
