<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| maintainer shell → promotion CLI | Command arguments and process context are untrusted until CLI, maintainer-secret, and closed identifier checks succeed. |
| immutable evidence ledger → activation service | Current dual-branch proof must be exact before an inactive revision can become effective. |
| browser/native API → reusable rules | Browser and generic native writes must not acquire the CLI promotion authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-20 | Elevation of Privilege | activation CLI | mitigate | Require CLI SAPI, deployment-owned maintainer secret file, strict named revision/proof IDs, and no HTTP route/UI control. |
| T-04-21 | Tampering | promotion inputs/evidence | mitigate | Reject unknown options and stale/mismatched immutable evidence; resolve projection details internally and call only `ActivateVerifiedRuleset`. |
| T-04-22 | Information Disclosure | command result/logs | mitigate | Fixed exit codes and redacted JSON/stderr; never emit secret, SQL, cache rows, household values, factors, source URLs, or complete proof IDs. |
| T-04-23 | Tampering | alternate promotion paths | mitigate | Deterministic spies/snapshots prove generic universal POST/PUT and all browser/API paths remain blocked while product-scoped native saves remain normal. |
| T-04-SC | Tampering | package installs | accept | No package installation is planned. |
</threat_model>
