## Trust Boundaries

| Boundary | Description |
|---|---|
| Companion client → `build_app()` route | API-key, variant, and opaque token are untrusted until the deployed handler checks them. |
| Secure route → capability service | Only the service may redeem an issued variant-bound handle; tests must not bypass it. |
| Immutable candidate → current planning HEAD | Post-candidate evidence must be enumerated, not inferred from a mutable ref or broad directory rule. |
| Test evidence → release decision | A stale route fixture or permissive allowlist can falsely certify secure media or release provenance. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-15-02 | Information Disclosure | Companion response/error mapping | mitigate | Assert generic 404 text and private/no-store/nosniff headers; prohibit URL, token, resolver, and exception disclosure. |
| T-02-15-03 | Tampering | Media provenance/evidence | mitigate | Test only the deployed handler and `SecureMediaResult` boundary; a legacy one-segment route is explicitly insufficient evidence. |
| T-02-15-04 | Denial of Service | Companion secure-media path | mitigate | Keep the fake service network-free and preserve existing secure-media bounded-redemption suite as a required paired command. |
