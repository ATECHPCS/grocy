From `GrocyAiContract`:
- `DecodeAndValidateRaw(string $raw, string $requestedGtin = ''): array` lexically walks raw JSON before `json_decode` and maps all contract defects to `GrocyAiContractException`.
- Suggestion fields are the six closed values `name`, `brand`, `package_size`, `product_group`, `quantity_unit`, and `food_type`; the final review reducer uses `reviewState.rows[field]`.
- The only permitted structured package-media source is `{ id: 'openfoodfacts', label: 'Open Food Facts' }`; the only permitted search alternative source is `{ id: 'searxng', label: 'Search result' }`.

From `GrocyAiService`:
- `EnrichByUpc` calls `Request` then `DecodeAndValidateRaw`; its injected transport is the deterministic PHP test seam.
- Production currently materializes `(string) $response->getBody()` and must instead reject oversized Content-Length and incrementally cap bytes before the contract lexical walk.

From the browser module:
- `validContract(data, requestedGtin)` must reject before `renderReview`.
- `renderReview` must never silently replace a prior `reviewState.rows[row.field]` row.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| External companion HTTP response → Grocy stream reader | Content length, stream bytes, and raw JSON nesting are untrusted and can exhaust PHP resources. |
| Raw JSON → PHP contract decoder | Duplicate keys, duplicate reviewed fields, and malformed schema must fail before lossy reduction. |
| Validated DTO → browser validator/reducer | Browser-delivered suggestions and provenance metadata must not overwrite a visible review row or stage a normal Save value. |
| Media evidence → user decision | Provider-supplied source labels must not impersonate structured Open Food Facts evidence. |
| Test fixture/evidence → phase verification | Synthetic adversarial coverage must demonstrate the real rejection and zero-write outcomes without private data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-16-01 | Denial of Service | Companion response reader | mitigate | Reject malformed/oversized Content-Length and cap streamed enrichment bytes at 65,536 before contract parsing. |
| T-02-16-02 | Denial of Service | Raw JSON lexical parser | mitigate | Limit recursive container depth to 64 and use the same finite JSON decoding depth. |
| T-02-16-03 | Tampering | Suggestion contract/reducer | mitigate | Require unique IDs and fields in PHP/browser, then defense-check `renderReview` before field-keyed assignment. |
| T-02-16-04 | Spoofing | Media provenance | mitigate | Bind kind/evidence to exact source ID+label pairs and test both crossed directions and label substitutions. |
| T-02-16-05 | Information Disclosure | Companion error mapping | mitigate | Preserve finite generic contract-invalid recovery and prohibit raw bodies, URLs, tokens, credentials, parser details, and traces in DOM/logs. |
| T-02-16-06 | Tampering | Persistence boundary | mitigate | Assert invalid browser data creates no review rows, final diff, staged native control/file, or mutation-route call before normal Save. |
| T-02-16-07 | Repudiation | Test/evidence integrity | mitigate | Keep raw depth and crossed-provenance fixtures deterministic, tagged, and run alongside focused browser and PHP checks. |
</threat_model>
