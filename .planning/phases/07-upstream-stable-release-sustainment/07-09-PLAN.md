## Trust Boundaries

| Boundary | Description |
|---|---|
| Module migration → native database | A Bootstrap must never shadow, alter, or drop a native Grocy table or lose household data. |
| Prod-shaped snapshot → migration harness | The harness must operate on a per-run copy, never prod, and re-runs must be deterministic. |
| Upgrade path → existing data | Adding bulk/capture tables to a Phase-3-shaped DB must preserve every prior row. |

| T-07-09-02 | Repudiation | Idempotency | mitigate | Double-run Bootstrap and assert zero additional diff on the second run on both branches. |
| T-07-09-03 | Denial of Service / Tampering | Upgrade-path data loss | mitigate | Assert native product/group/conversion counts (444/21/80) and prior module rows are preserved after the upgrade. |
