## Phase Goal

**As a** household maintainer, **I want to** be told when a proposed change no longer matches the world I reviewed, **so that** a stale plan can never silently overwrite a value that changed after I generated it.

<objective>
Deliver per-item optimistic concurrency: a zero-write pre-apply check re-reads each selected item's current value and refuses any item whose value has drifted from the reviewed before-image, marking it `conflict` and removing it from the apply set — while the remaining valid items stay eligible.

Purpose: bind apply to present reality (as selection bound review to the artifact), the only stale-plan safety Phase 5 uses.
Output: `DetectApplyConflicts` plus its focused conflict/no-conflict/no-partial-write tests. The transactional apply that consumes this set is 05-07.
</objective>

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| stored before-image → current reality | The reviewed before-image is a claim about the past; the write may only proceed if present reality still matches it. |
| conflict judgement → apply set | A stale or unreadable value must remove an item, not silently overwrite. |
## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-05-06-01 | Tampering | stale before-image | mitigate | Re-read current value through the live read path and compare exactly; drift → per-item `conflict`, no write. |
| T-05-06-02 | Spoofing | plan-as-truth | mitigate | Never use `before_image_json` as the current value; a corrupt/absent image fails closed to `conflict`. |
| T-05-06-03 | Denial of Service | partial write on conflict | mitigate | Detection is pure read; a conflicted item drops from the set without aborting valid siblings or writing. |
| T-05-06-SC | Tampering | package installs | accept | No package installation is planned. |
</threat_model>
