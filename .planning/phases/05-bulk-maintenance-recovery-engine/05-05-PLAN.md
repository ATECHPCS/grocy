## Phase Goal

**As a** household maintainer, **I want to** select or reject each proposed change and see the complete diff of exactly what I selected, **so that** I approve a bulk change I have actually reviewed and nothing I did not.

<objective>
Deliver per-item review: over a stored dry-run plan the user toggles each item's selection, the selection persists with the plan, and the complete selected diff is rendered read-only. The apply set becomes exactly the selected, non-conflicted items.

Purpose: bind human review to the artifact that will later apply, without opening any write path beyond the module-owned selection flag.
Output: `SetItemSelection` plus a selected-diff read, MASTER_DATA_EDIT-gated read endpoints, and the Bootstrap 4 review surface with its Node test.
</objective>

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| browser review UI → selection endpoint | The item list, targets, and operation are server-owned; the browser may supply only a seq and a boolean. |
| stored plan → selected diff | The reviewed diff must be the immutable before/proposed content, not a re-derived or browser-supplied value. |
## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-05-05-01 | Tampering | selection endpoint | mitigate | Closed `{selected}` body via `array_intersect_key`; write only the `selected` flag; validate seq against the plan's own items. |
| T-05-05-02 | Spoofing | free-form apply set | mitigate | The apply set is derived server-side from stored `selected` rows; no browser item list is ever accepted. |
| T-05-05-03 | Information Disclosure | rendered diff | mitigate | HTML-escape all before/proposed values; the diff exposes only the plan's own item content. |
| T-05-05-04 | Elevation of Privilege | review/selection routes | mitigate | Every endpoint requires authenticated `MASTER_DATA_EDIT` before any read or flag write. |
| T-05-05-SC | Tampering | package installs | accept | No package installation is planned. |
</threat_model>
